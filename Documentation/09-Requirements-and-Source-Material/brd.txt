EXECUTIVE SUMMARY



SMAART Minds is a comprehensive, AI-powered Learning Management and Career Readiness Platform built for higher-education institutions across India. The platform serves as a personalised 24/7 career coach for every enrolled student, bridging the critical gap between academic output and industry expectations.



The Three Problems SMAART Solves

Lack of self-awareness — Students graduate without understanding their own strengths, weaknesses, and professional skill gaps.

Lack of career readiness — Academic curricula teach domain knowledge but not the behavioural, digital, and professional execution skills that employers prioritise.

Lack of verifiable credentials — Students have no credible, tamper-proof way to demonstrate real skill growth beyond a paper degree.

2.4 Security Architecture

Security is enforced at four layers simultaneously:

Transport Layer: HTTPS enforces encrypted data transmission across all endpoints.

Application Layer: Helmet sets security HTTP headers (CSP, X-XSS-Protection); CORS restricts API access to authorised origins.

Authentication Layer: JWT tokens carry encrypted role claims validated on every API call; bcrypt protects passwords; OTP-based 2FA prevents credential theft.

Data Layer: Role-Based Access Control (RBAC) ensures every database query is scoped to the requesting user's authorised data range. College Admin queries are auto-filtered to college_id — cross-institution data leakage is architecturally impossible.




SECTION 3 — USER (STUDENT) DASHBOARD



The Student Dashboard is the primary user-facing system. It serves as the central hub for the student's entire journey — from first login through to certificate issuance and career readiness. The journey is divided into 7 sequential phases, each gating access to the next.



3.1 Phase 1 — Authentication & Access

Landing Page & Institution Selection

Every student journey begins at the SMAART Minds landing page. The very first mandatory interaction is institution selection — a modal requiring the student to select their college from a verified partner list before any further action is possible. This is not merely UX — it scopes the student's access to institution-specific content and validates the session against the correct institutional domain.



Technical implementation: session storage persists the selected institution; the system validates partnership status on the backend before proceeding.



First-Time Login & OTP Verification

Student receives credentials (Student ID + temp password) from College Admin.

Enters credentials on the student portal login page.

Backend validates credentials; generates a 6-digit time-based OTP sent to registered email/mobile.

OTP expires in 5 minutes; resend available after 60 seconds; account locked after 5 failed attempts.

On valid OTP entry, student proceeds to mandatory password change.



Mandatory Password Change

First-time login flag triggers forced password change. Requirements: minimum 8 characters, one uppercase, one number, one special character. A password strength indicator guides the process. Once completed, the flag is cleared and the student proceeds to onboarding.

3.7 Phase 7 — Certification & Skills Passport

Personal Learning Velocity Index (PLVI)

The PLVI measures not where a student ends up but how fast they improved. Formula: PLVI = (S_current − S_baseline) ÷ T_days. This rewards effort and learning agility over prior advantage — making it more equitable for students from diverse backgrounds.

Certificate Issuance Logic

C1: Issued after passing T2 (score ≥ 60%). Prerequisites: T1 completed.

C2: Issued after passing T3 (score ≥ 60%). Prerequisites: C1 must be held.

C3 Diploma: Issued after passing T4 (score ≥ 60%). Prerequisites: C1 and C2 must be held.

Integrity Status Check: Any unresolved assessment integrity violations block certificate issuance pending admin review.



Skills Passport (ICAS)

The Skills Passport (Industry Credentialing and Assessment System) is the consolidated professional identity document from the student's entire journey. It includes: all T1–T4 assessment scores, band progression, skill acquisitions, course completions, certifications earned, and final PLVI score. Rendered with Recharts (Skill Radar Chart, growth timelines). Downloadable as professional PDF. Shareable with employers as proof of verified, tested competence.



Placement Probability Index (PPI)

PPI = (Assessment Score × 30%) + (Completion Rate × 50%) + (Growth Average × 20%). This weighting deliberately prioritises effort (course completion rate) as the biggest factor, reinforcing that consistent action matters more than raw ability.

4.2 Complete Career Intelligence Processing Flow

Phase 1: Student Onboarding (6-Step Profile Collection)

Personal Details: Full Name, Email, Phone, Registration Number → saved to Prisma + MongoDB

Education: Up to 3 entries (Level, Domain, Degree Group, Specialisation, University, Graduation Year) → cascading dropdowns from educationData.json

Primary Career Preference: Sector → Job Family → Role → Career Direction ID

Secondary Career Preference: Same structure as primary

Tertiary Career Preference: Same structure as primary/secondary

Skills: Multi-select or free-text skills input



Phase 2: Career Intelligence Engine Processing

On form submission, the engine runs 12 sequential steps:

Cache Check: Generate profile hash; check records directory for existing analysis → return immediately if found

Safety Backup: Create trace ID; save initial record to JSON file with status "pending_analysis"

Resolve Preferences: Extract primary/secondary/tertiary careerDirectionId and role from studentData

Fetch Direction Data: Query MongoDB career_agent_data collection for each preference

Fetch Role Data: Query MongoDB careerroles collection for each resolved role

Transform Role Data: Extract domain_skills → tech_skills[]; ai_skills → ai_tools[]; normalise skill names

Calculate Direction Score: Degree Match (35%) + Skill Match (45%) + Experience Match (20%) → score 0.0–1.0

Determine Zone: ≥0.6 = Green (Strong alignment), ≥0.3 = Amber (Moderate), <0.3 = Red (Weak)

Calculate Skill Gaps: Compare student skills vs role required skills → missingSkills[], matchingSkills[]

ML Enrichment: Send skills to ML Service → semantic skill extraction + success probability (0.1–0.95)

Zone Matrix Lookup: Cross-reference zone_matrix.json and market_data.json for validated zone data

Generate 5-Tab Role Report for each career preference (primary, secondary, tertiary)

The admin portal and student portal are entirely separate applications — students attempting to log in through the admin portal are explicitly rejected with a warning directing them to the student application.

5.2 Admin Authentication

Two-factor authentication identical in structure to student flow but operating on a separate credential space:

Enter email and password on admin portal login page

System validates credentials and checks role flag

6-digit OTP generated and sent via email — 60-second unresendable countdown

5.6 Analytics & Reporting

Delta Comparison System

5.9 Coaching & Escalation Subsystem

Coaches are assigned to specific college cohorts or departments. Escalation triggers: student consistently fails assessments (automated), session reported as inappropriate (manual), Emotion Coach detects high-risk keywords (automated). Each escalation creates a micro-forum visible only to assigned Admin and Coach. Marked Resolved only after documented action — full audit trail of intervention history.
